# WLE Filter

Автоматична попередня перевірка фото для **Wiki Loves Earth**: відсіює розмиті кадри,
фото з людьми, таблички/текст, дублікати та фото з малою роздільністю.
Має веб-інтерфейс для ручної перевірки та налаштування чутливості окремо
для **якісної** і **кількісної** номінацій.

## Швидкий старт

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py serve                                    # → http://127.0.0.1:8000
```

1. **+ Новий прогін** → оберіть номінацію та джерело:
   * **Категорія Commons** — напр. `Wiki Loves Earth Ukraine 2026 - Quality`;
   * **Локальна папка** — підпапки першого рівня вважаються авторами (`photos/Автор/фото.jpg`).
   Поле «Ліміт» зручне для першого пробного прогону на 50–100 фото.
2. Поки йде аналіз, результати з'являються в галереї.
3. Ліва панель **Чутливість**: повзунки, вмикання фільтрів, гістограми розподілу
   (клік по гістограмі ставить поріг). Вердикти перераховуються миттєво — **аналіз фото
   не повторюється**.
4. Перевірка: клік по фото відкриває перегляд з рамками знайдених людей.
   Клавіші: `←/→` навігація, `A` залишити, `R` відхилити, `U` скинути, `B` рамки, `Esc` закрити.
   Ручне рішення має пріоритет над автоматичним.
5. **Експорт** — CSV (сумісний зі старим `progress.csv` + нові колонки) або JSON для інтеграції.

Прогін можна поставити на паузу, закрити сервер і продовжити пізніше — уже оброблені
фото не обробляються повторно.

### З телефона чи планшета

```bash
python main.py serve --lan
```

Сервер виведе адресу на кшталт `http://192.168.1.23:8000`. Відкрийте її на пристрої,
підключеному до тієї ж Wi-Fi-мережі. Якщо не відкривається, дозвольте Python у брандмауері
(Windows запитає при першому запуску).

> ⚠ Входу з паролем немає: у режимі `--lan` будь-хто в цій мережі може переглядати фото,
> змінювати рішення й бачити назви папок на комп'ютері. Не вмикайте його в публічних мережах.

Інтерфейс адаптивний:
* **комп'ютер (≥1100 px):** панель чутливості зліва;
* **планшет:** панель чутливості висувається кнопкою «⚙ Чутливість»;
* **телефон:** дві колонки карток, компактна шапка, вкладки й фільтри гортаються вбік;
* **перегляд фото на сенсорному екрані:** свайп вліво/вправо — наступне/попереднє, свайп вниз — закрити.

### Без інтерфейсу

```bash
python main.py run --category "Wiki Loves Earth Ukraine 2026 - Quality" --nomination quality
python main.py run --folder ~/photos --nomination quantity --limit 100
python recount.py --run 1 --nomination quantity        # перерахувати з іншим пресетом
python recount.py --legacy-csv ~/Desktop/wle_results/progress.csv   # старий формат v2
```

Дані (база SQLite, кеш мініатюр, збережені пресети) лежать у `wle_data/`;
шлях змінюється змінною `WLE_DATA_DIR`.

## Фільтри та чутливість

| Фільтр | Метрика | Відсіює, коли | Якісна | Кількісна |
|---|---|---|---|---|
| Розмитість | дисперсія Лапласіана (на 600 px) | метрика **<** порогу | 200 | 100 |
| Людина | YOLOv8n, клас «person» | упевненість ≥ X **і** площа ≥ Y | 0.25 / 5% | 0.25 / 15% |
| Табличка/текст | частка кадру з текстоподібними блоками | ≥ порогу | 15% | 25% |
| Дублікати | відстань Геммінга dHash/pHash | ≤ порогу | 12, серед усіх | 10, у межах автора |
| Роздільність | Мп оригіналу | < порогу | вимк. (2 Мп) | вимк. |

Значення пресетів — стартові; відкалібруйте їх на реальній вибірці й натисніть
**Зберегти в пресет**. Для кожного прогону пороги також зберігаються окремо.

**Чому «наживо» працює для всіх порогів.** Аналіз зберігає сирі дані: усі детекції людей
з упевненістю ≥ 0.05 (з рамками), обидва хеші, розміри оригіналу. Тому навіть поріг
упевненості детектора і поріг дублікатів змінюються без повторного прогону.

Оригіналом серед дублікатів вважається раніше завантажене фото.
Локальні фото перед аналізом зменшуються до 800 px по ширині — так само, як мініатюри з Commons,
тож пороги однаково працюють для обох джерел.

## Інтерфейс і Wikimedia Codex

Інтерфейс побудовано на [Wikimedia Codex](https://doc.wikimedia.org/codex/latest/) v2.6.0 —
справжніх дизайн-токенах і CSS-only компонентах (кнопки, перемикачі, вкладки, поля, select,
повідомлення, info chip, dialog, смуга прогресу). Файли лежать у `wle_filter/static/codex/`,
тож інтерфейс працює без збірки й без інтернету.

* **Тема:** кнопка в шапці перемикає авто / світла / темна; вибір запам'ятовується в браузері.
  Темна тема — офіційні токени Codex `mode-dark`.
* **Оновлення Codex:** `npm install @wikimedia/codex @wikimedia/codex-design-tokens`,
  потім `python tools/update_codex.py node_modules`.
* Codex поширюється під GPL-2.0-or-later.

## Архітектура

```
wle_filter/
  config.py    пороги (Thresholds) і пресети номінацій
  analysis.py  сирі метрики фото — не залежать від порогів
  verdict.py   пороги + метрики → причини і вердикт (чисті функції)
  sources.py   категорія Commons (pageid, автор, розміри) і локальна папка
  store.py     SQLite: прогони, метрики, ручні рішення
  worker.py    фонова відновлювана обробка
  server.py    FastAPI: REST API + static/index.html
main.py        CLI: serve | run
recount.py     перерахунок і експорт
```

REST API документується автоматично: `http://127.0.0.1:8000/docs`.

## Інтеграція з wlxjury (план)

[wlxjury](https://github.com/UkrainianWiki/wlxjury) (Scala/Play) ідентифікує фото за
`pageId` з Commons — саме це поле фільтр зберігає та віддає в експорті. Варіанти:

1. **Імпорт результату** — JSON-експорт (`page_id`, `verdict`, `reasons`, `metrics`)
   завантажується в wlxjury, напр. як відбір першого раунду або позначки для організатора.
2. **Сервіс** — wlxjury викликає REST API фільтра (`POST /api/runs`, `POST /api/runs/{id}/results`).

Ядро (`analysis` + `verdict`) не залежить від веб-шару, тому його можна загорнути в будь-який з варіантів.
